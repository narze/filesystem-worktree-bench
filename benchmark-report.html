Method and limits

Reproducible workload and timing
  • Repository: eventpop/eventpop, commit 0e0499f42444f1e4b2c0a6d11fc8043b42be295a, 10,055 tracked files.
  • pnpm 11.18.0; Node on PATH 24.22.1. pnpm carries a separate packaged runtime; the Linux wrapper's embedded Node v26.0.0 was verified. PATH Node is not the pnpm runtime.
  • One warmup batch for each worker count, followed by ten measured rounds. Worker-count order is shuffled each round with seed 42.
  • Each batch runs parallel detached Git worktree creation, waits, runs parallel offline dependency installs, waits, then deletes all trees concurrently with Python shutil.rmtree. Git metadata pruning and setup are outside the timers.
  • Timed installs use --offline --frozen-lockfile --ignore-scripts and a dedicated warm package store on the target filesystem. Internet downloads and SSH latency are outside the timers. App/database provisioning, Ruby dependencies and native build scripts are excluded.
  • Automatic imports used clones on Btrfs/APFS and hard links on ext4. Linux installed 1,318 packages; macOS installed 1,319 due to platform-specific dependencies.
  • Workers start each phase behind a barrier. Times use the machine's monotonic clock. Total is the sum of phase wall times. Throughput is workers divided by total, summarized per batch.
Interpretation and reliability
  • This is a whole-system comparison. Different CPUs, RAM, drives, OS/Git/Python versions, power states, free space and background activity prevent attributing a result to APFS, Btrfs or ext4 alone.
  • Caches were warm and uncontrolled. There was no cache eviction or fsync/storage flush; these are command-completion latencies, not durable-write latencies.
  • Both Btrfs mounts use zstd:3 and LUKS, but the desktop uses noatime and the ThinkPad uses relatime. The Macs use APFS/FileVault. Debian uses ext4/relatime on a rotational HDD.
  • Desktop applications and services remained active. Debian had swap in use before setup; a warmup snapshot showed 92% I/O wait, blocked tasks and active swap-out. This is observed context, not proof that any single factor caused its timings.
  • The M4 Pro had one failed parallel Git checkout in round 9: a commondir metadata read error. Its first 33 successful samples were preserved and seven missing samples resumed using the original batch function. Failed-attempt timing is excluded; the original error is retained separately. All three new machines and the desktop had no failed measured batches.
  • Ten samples describe these runs. Ranges are observed extremes, and small differences are not evidence of statistical significance. Inventory power/memory snapshots were collected after benchmarking; benchmark-start free space comes from each original result.

Cleanup and evidence

All five temporary benchmark datasets and dedicated stores are removed. Results, logs, hardware inventories and the runner are retained locally. Original Eventpop checkouts were not modified, and SSH sessions are closed.
