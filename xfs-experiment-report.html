Protocol and configuration

  • Original Eventpop commit 0e0499f42444f1e4b2c0a6d11fc8043b42be295a, pnpm 11.18.0, PATH Node 24.22.1. The original batch timing function is unchanged and verified by SHA-256.
  • Each target gets its own Git copy and package store. One warmup plus one excluded preflight batch per worker count precedes measurements. All setup downloads and preflight samples are outside this table.
  • Within each measured round, worker-count order uses seed 42. At each worker count, the three filesystem cases run sequentially in randomized order using seed 73. No simultaneous benchmark cases compete for disk access.
  • Workload: parallel detached worktree creation, parallel offline frozen dependency installs with scripts disabled, then parallel deletion. Measures command completion with no fsync or cache eviction.
  • Two 16 GiB preallocated regular image files on the same native Btrfs/LUKS/NVMe volume. Their outer backing files have NOCOW/NODATASUM, which also prevents outer compression. Both still use the host Btrfs allocation and storage stack.
  • An earlier pilot was stopped after detecting that mkfs.xfs had recreated a sparse image. Its data is excluded. The corrected experiment restores and verifies full preallocation after formatting; the allocation evidence and excluded pilot records are preserved.
  • Guest Btrfs: noatime, zstd:3, ssd, nodiscard, mkfs defaults. Guest XFS: noatime, nodiscard, metadata CRC and reflink enabled, no VDO. Native Btrfs is a fresh control, not the older desktop timing run.
  • Formatting tools: xfsprogs: mkfs.xfs version 7.2.0; btrfs_progs: mkfs.btrfs, part of btrfs-progs v7.1. Full mkfs output, mount options, schedule, host inventory, raw timings, and preflight records are retained in xfs-results/.

Interpretation limits

  • Matched images reduce the difference in layering, but loop-device caching, host Btrfs metadata, allocation, compression and guest filesystem defaults remain part of the result. Native Btrfs versus guest XFS is not a symmetric bare-metal comparison.
  • No storage flush separates cases. Asynchronous writeback from an earlier case can overlap later cases; randomized ordering reduces bias but does not remove this source of variation.
  • This tests plain XFS. Theo also discusses XFS with VDO, a separate block-level deduplication and compression layer. That configuration is not measured here. Linux VDO documentation.
  • Automatic package import behavior and foreground/background load are included. Ten samples per worker count provide descriptive medians and ranges; small differences are not proof of statistical significance.
  • A stronger filesystem-only conclusion requires a dedicated disposable device or raw partition, tested sequentially on the same hardware. No existing partition was reformatted for this experiment.

Cleanup

All temporary filesystems were unmounted, loop devices detached, and images and datasets removed. Allocated scratch footprint removed: 33.02 GiB. Installed xfsprogs/liburcu tools remain available.
